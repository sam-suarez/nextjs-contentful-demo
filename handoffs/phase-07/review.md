Notes:
- Possible R13 failure: the diff removes `await connection()` from src/app/products/[slug]/page.tsx. The deleted comment said it made `notFound()` and `redirect()` return real 404/307 statuses. Both calls now run inside a streamed boundary, so an unknown slug probably returns 200. If verify-ssr asserts 404 for `detail_unknown` or `detail_badslug`, that check will fail. The spec's Out of scope says the 404 is "still JS-handled", which conflicts with the deleted comment. qa's run will settle it. A logged-in visitor on `/login` and a logged-out visitor on a Set B slug still get their redirects from the proxy first.
- Mobile layout change: `HEADER_SESSION_SLOT` is `w-full` below `md` (ui-classes.ts:24). The logged-out Sign in button now drops to its own row under the logo on mobile. Logged in, the name is truncated (`md:max-w-56`, site-header.tsx:66) and the badge sits above the name inside a 48 px slot. Below 360 px the banner reserves three lines (ui-classes.ts:32). design.md Responsive ("stack everything below md") supports this, but the spec lists "changing layout" as out of scope, so the human may want to see it. Below `md`, the badge plus a `text-sm` line may be taller than `h-12` and overlap the banner border. I can't see the badge classes.
- Weak R10 test: the CLS check passes even if the boundaries resolve before first paint. The probe records that skeleton nodes were in the DOM, not that they were painted. The file header says the test covers R8 (outer size), but it measures no sizes.
- The hard-coded chip widths (skeletons.tsx:62) and the logged-out banner wrapping near the `sm` breakpoint (about 640-660 px) depend on fonts. Neither is covered at the two measured viewports.
- In the R8 row, I estimated "about one row taller" from class names in the diff; I did not measure it.

Where the instructions got in the way:
- R8 asks for "the same outer size as the content it replaces", but `CatalogSkeleton` takes no props, so it can't know how many cards there will be: 12 logged in, 8 logged out, fewer for `/?category=bath`. It also can't follow product-specific title or description lengths on the detail page. Read literally, R8 can't be met for the grid's total height, so I judged the catalog on per-card and filter-card dimensions only.
- R8 lists "e2e (R10)" as its check, but a CLS measurement can't see size differences inside a boundary that is replaced wholesale. With nothing after the catalog or detail boundary in the viewport, R10 says nothing about those two skeletons' sizes.
- R3 and design.md say `rounded-md` for every non-pill block, images included, while R8 asks for matching card frames. Those two pull in different directions for inputs and image frames.

**Orchestrator decision:** back to ui (round 2), fix input this file. R8(b) asks for evidence the diff can show; the builder may make sizes structurally shared (constants visible in the diff) rather than measured.
